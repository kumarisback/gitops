Observability Pipeline Map

How API logs, server logs, traces, and metrics get from order-service / user-service to Grafana — every hop, port, Helm chart, and the exact repo file that configures it, so a new environment can be wired up and verified without re-deriving any of it.

End-to-end signal flow

three lanes converge on one Grafana

Verify a signal in under a minute

run against any env — swap the namespace

API logs

Per-request access log lines only — method, path, status, duration.

kubectl port-forward svc/kube-prometheus-stack-grafana 3000:80 -n monitoring

Grafana → Explore → Loki:

{namespace="development", container=~"order-service|user-service"} | json | logger=~"access\..*"

Server logs

Everything except the access log — startup, business logic, unhandled exceptions.

Same datasource, inverted filter:

{namespace="development", container=~"order-service|user-service"} | json | logger!~"access\..*"

A real exception should render as one log line with a populated exception field — if it's split across several lines, the encoder or the shipper's multiline stage needs a look.

Traces

Confirm a request's spans reached Tempo and log correlation is wired up.

Grafana → Explore → Tempo → TraceQL:

{ resource.service.name = "order-service" }

Then in Loki, confirm a matching trace_id field shows up on the log lines from that same request.

Metrics

Confirm Prometheus is actually scraping both services.

Grafana → Explore → Prometheus:

up{namespace="development", job=~"order-service|user-service"}
rate(http_server_requests_seconds_count{namespace="development"}[5m])
